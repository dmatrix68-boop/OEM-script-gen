Version 2.1 bringt die Einstellungen eines Referenzbenutzers mit aufs Installationsmedium. Profile aus [Win-ProfileKit](https://github.com/dmatrix68-boop/Win-ProfileKit) (`.pkprofile`) kommen zusammen mit `profilekit.exe` ins Paket und werden im OEM-Lauf wiederhergestellt – Windows-Einstellungen für jeden neuen Benutzer, Programmeinstellungen nach den Installationen.

## Download

**`OEM-Script-Generator-v2.1.zip`** herunterladen, entpacken, `index.html` im Browser öffnen.

## Neu

- **Seite *Profile* (Win-ProfileKit):** `profilekit.exe` und `.pkprofile`-Dateien aufnehmen, die mit `profilekit collect --zip` bzw. `capture --zip` auf einem Referenzsystem entstehen.
  - Je Profil lässt sich ein **Zielbenutzer** angeben. Leer bedeutet: der Benutzer der ersten Anmeldung.
  - Die **winget-Pakete** der Profile lassen sich per Klick in die Anwendungen übernehmen.
  - `.pkprofile`-Dateien werden auch über *Import* und per Drag & Drop erkannt. Der Generator liest `profile.json` direkt aus dem Archiv.
- **Wiederherstellung in zwei Schritten:**
  - **Phase 1:** `Restore-Profile-P1.ps1` schreibt die Windows-Module der Profile (`windows.*`) ins Default-Profil. Jeder neue Benutzer erbt sie, wie bei den Tweaks.
  - **Phase 2:** `Restore-Profile.ps1` wendet die Profile nach `Install-Apps.ps1` an. Ohne Zielbenutzer auf den angemeldeten Benutzer (auch wenn Phase 2 als SYSTEM läuft), mit Zielbenutzer offline auf dessen Konto. Konten ohne Profil legt `profilekit.exe` selbst an.
  - Die Ausgabe von `profilekit.exe` steht im Protokoll. Exitcode 2 (Teilerfolg) gilt als Warnung.
- **Ablage** unter `$OEM$\$1\Install\ProfileKit`. Fehlt eine Datei, etwa nach dem Laden einer Projektdatei, entsteht an ihrer Stelle eine Hinweisdatei. Profile und `profilekit.exe` stehen wie eigene Dateien nicht in der Projektdatei.
- **Hilfe (F1) und README** beschreiben die Profile in beiden Sprachen.
- **Test in GitHub Actions:** `tools/test-profilekit.js` prüft Import und Erzeugung mit einem echten Profil (`samples/Beispiel.pkprofile`). Die neuen Module laufen außerdem durch die PowerShell-Prüfungen.

**Hinweis:** Profile enthalten keine Zugangsdaten, wohl aber Lizenzdateien wie `rarreg.key`.

*English:* Version 2.1 adds a **Profiles** page for [Win-ProfileKit](https://github.com/dmatrix68-boop/Win-ProfileKit). It takes `profilekit.exe` and `.pkprofile` files captured on a reference system, with an optional target user per profile, and can add the profiles' winget packages to the applications with one click. `.pkprofile` files are also recognized on import and drag & drop. During setup, `Restore-Profile-P1.ps1` writes the Windows modules into the default profile in phase 1, and `Restore-Profile.ps1` applies the profiles after `Install-Apps.ps1` in phase 2 – to the signed-in user or offline to the target user's account. Exit code 2 of `profilekit.exe` counts as a warning. Profiles contain no credentials, but may contain licence key files such as `rarreg.key`. A new CI test checks import and generation with a real profile. Download `OEM-Script-Generator-v2.1.zip`, unpack it and open `index.html`.

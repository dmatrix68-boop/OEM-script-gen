Version 1.2 macht große Pakete alltagstauglich. Treiber mit 1–2 GB lassen sich direkt auf den USB-Stick exportieren, ohne ZIP und Entpacken. Das ZIP kennt jetzt ZIP64 und damit keine 4-GB-Grenze mehr. Getestet wurde das auf Windows mit einem vollständigen NVIDIA-Grafiktreiber (220 Dateien, 945 MB).

## Download

**`OEM-Script-Generator-v1.2.zip`** herunterladen, entpacken, `index.html` im Browser öffnen.

## Neu

- **In Ordner exportieren** (Chrome, Edge): Schreibt die Struktur direkt in einen Ordner, etwa ins Wurzelverzeichnis des USB-Sticks.
  - Vorhandene Ordner `$OEM$`, `sources\$OEM$` und `$WinPEDriver$` im Ziel werden nach Rückfrage geleert. Alles andere bleibt unberührt.
  - Der zuletzt gewählte Exportordner wird gemerkt.
  - **DLLs und andere gesperrte Dateitypen:** Chrome schreibt `.dll`, `.ini`, `.cfg` und `.manifest` nicht unter ihrem Namen in Ordner. Der Export legt sie als `*.oemrename` ab, und `Install.ps1` benennt sie vor dem ersten Modul zurück.
  - Für Treiber unter `$WinPEDriver$` geht das nicht, weil dort kein Skript läuft. Dafür das ZIP verwenden.
- **ZIP64:** Ab 4 GB oder 65.535 Dateien schreibt der Generator automatisch ZIP64. Das entpacken der Windows-Explorer und 7-Zip.
  - Große Dateien werden direkt von der Platte übernommen statt im Arbeitsspeicher gesammelt.
  - Das ZIP wird stückweise geschrieben.
- **Eigene Dateien merken** (Chrome, Edge): Installer unter „Eigene Dateien“ werden beim Laden der Projektdatei direkt wieder eingebunden. Braucht Chrome erneut die Freigabe, genügt ein Klick auf **Quellen einbinden**.
- **Treiberordner** müssen nach dem Laden einmal neu gewählt werden, denn Chrome gibt gemerkte Ordner nur ohne DLLs heraus. Angezeigt wird der Ordner, aus dem das Paket zuletzt kam.
- **Zielordner `Install\Office`** unter „Eigene Dateien“ für die `setup.exe` des Office Deployment Tools. Ist das Office-Modul aktiv, landet eine hinzugefügte `setup.exe` automatisch dort.

## Korrigiert

- **„Name is not allowed“** beim Ordner-Export: Gesperrte Namen brechen den Export nicht mehr ab.
  - Nicht rettbare Namen werden übersprungen und am Ende aufgelistet, etwa `con.txt`, `Thumbs.db` oder `desktop.ini`.
  - Jede Fehlermeldung nennt den Pfad der Datei.
- **„Cannot close a ERRORED writable stream“** beim ZIP: Diese Meldung verdeckte den eigentlichen Fehler, jetzt erscheint der Originalfehler mit Dateinamen.
- **Nicht mehr lesbare Quelldateien:** Ist eine Datei seit dem Hinzufügen geändert, verschoben oder gelöscht, meldet Chrome nur „network error“. Der Generator erkennt diesen Fall jetzt und markiert die Datei als fehlend.
- **Abbruch während Phase 2:** Nach einem Abbruch mit Neustart konnte die Laufmarkierung einen fremden Prozess für einen laufenden Durchgang halten. Dann wäre die Phase dauerhaft übersprungen worden.
- **Protokoll:** `Diagnose.ps1` meldet übrig gebliebene `*.oemrename`.

*English:* Version 1.2 adds **Export to folder** (Chrome, Edge), which writes the structure straight to the USB stick. File types Chrome refuses to write (`.dll`, `.ini`, `.cfg`, `.manifest`) are stored as `*.oemrename`, and `Install.ps1` renames them back before the first module. The ZIP now uses **ZIP64** above 4 GB or 65,535 files and takes large files straight from disk. Files under *Own files* are attached again when a project is loaded, and a new target folder `Install\Office` holds the Office Deployment Tool's `setup.exe`. Fixes cover blocked names during folder export, a masked ZIP write error, source files that are no longer readable, and a stale run marker after an aborted phase. Tested on Windows with a full NVIDIA graphics driver (220 files, 945 MB). Download `OEM-Script-Generator-v1.2.zip`, unpack it and open `index.html`.
